# agent-builder：把确认过的方案做成 Agent 产品

这是 Agent 工坊流程的开发环节，接在 `agent-prd` 后面：

```
点子 ──agent-prd──▶ PRD.md + 方案.md ──用户确认──▶ agent-builder ──▶ 可运行、可交付的 Agent
```

> **模型已经知道如何成为 Agent。你的工作是给它一个值得行动的世界，并把它交付上线。**
>
> Agent = 模型（智能，已训练好）+ Harness（你写的代码：工具、知识、观察、行动接口、权限）

## 开工前：确认输入

1. **找到 PRD.md 和 方案.md**。agent-prd 默认放在 `docs/{产品名}/`；Agent 工坊引擎放在 `out/{产品名}/`。找不到就问用户在哪。
2. **没有这两份文件**：不要凭一句话直接开写。告诉用户先用 agent-prd 把需求和方案做出来，原因是没有方案时写出的代码方向一错就要整个返工。用户坚持要先看个能跑的原型时，可以用 `scripts/init_agent.py --level 0` 生成最小骨架，并明确告诉他这只是演示，不是产品。
3. **看方案的状态和待确认清单**。还有没回答的「需求问题」时，告诉用户哪些地方会按默认假设实现，请他确认可以先这样开工。所有按假设实现的地方，都要记进项目 README 的「按默认假设实现」一节，以后他回答了问题才知道要改哪里。

## 读方案的方式

方案的每一部分都对应一块代码，开发时逐项对照，不要另起一套设计：

| 方案里的部分 | 对应的代码 |
|---|---|
| 组件选型（必选的组件） | 要实现的机制。每个组件的参考实现见下面的「组件参考」 |
| 工具清单 | 每个工具一个函数 + 一份 JSON schema；「先问人」的工具要过权限确认，「禁止」的工具不注册 |
| 系统提示词草案 | 放进配置或提示词文件，不要写死在代码里 |
| 安全边界与降级策略 | 每条「场景 → 处理方式」都要有对应的代码路径和测试 |
| 可观测性 | 日志、指标、轨迹记录 |
| 技术栈与部署形态 | 语言、启动命令、配置与密钥外置方式 |
| 测试设计 | 测试用例 |

方案里标「二期」的组件第一版不做，但在代码里留好挂接点（例如工具注册表、钩子接口），并在 README 写明。

## 开发分三层递进

每一层都要能运行，再进入下一层：

1. **骨架**：能跑的 agent loop + 方案里的工具 + 系统提示词。一条命令能起，能完整走一遍核心闭环。
2. **硬化**：错误处理、超时、重试、日志、配置化（密钥放 `.env`）、权限检查，以及方案里的每一条降级策略。
3. **产品化**：其余必选组件集成、测试、启动文档和部署脚本、README。

起步可以用脚手架生成项目骨架（只用 Python 标准库，生成的项目本身依赖见它的 requirements.txt）：

```bash
python3 ${CLAUDE_SKILL_DIR}/scripts/init_agent.py {项目名} --level 1 --path {输出目录}
```

level 0～4 依次是：最小循环、加读写工具与生产基础（配置、日志、重试、权限检查点、轨迹）、加任务规划、加子 Agent、加技能加载。按方案选型挑最接近的一级，再按方案增删。

## 代码放在哪

- 用户自己的项目：放在项目里合适的位置（通常是项目根目录或 `{产品名}/`），开工前告诉用户。
- PRD 和方案来自 Agent 工坊引擎的 `out/{产品名}/`：代码只能写进 `out/{产品名}/skeleton/`，这是引擎的规矩（`verify` 只检查这个目录）。

## 生产级验收标准

同时满足这六条才算产品，否则只是 demo。交付前逐条对照，并在 README 里写明每条怎么做到的：

1. **可运行**：一条命令能起，配置与密钥外置
2. **可容错**：工具失败、幻觉、超时、越权都有降级路径
3. **可观测**：有日志、指标、轨迹数据
4. **可测试**：循环与分派有单测，权限 / 安全有边界测试
5. **可部署**：有明确的部署形态与启动文档
6. **可度量**：有对齐 PRD 第 5 节的成功指标，并能采集

## 需求变了怎么办

开发中或交付后用户提出新需求、改需求：**先改文档，再改代码**。用 agent-prd 技能给 PRD 升版、更新方案（它会在方案开头写出「本版变化」），然后按「本版变化」增量修改代码：只改受影响的部分，不整个目录重建，保留用户手改过的文件。

## 关键原则

1. **模型就是 Agent**：代码只负责跑循环、提供工具、守住边界，判断交给模型。
2. **方案是依据**：选型、工具、权限都照方案来；发现方案有问题，回到 agent-prd 改方案，不要在代码里悄悄另做一套。
3. **最小实现**：只实现方案里必选的组件。
4. **未知不编造**：方案里待确认的地方按默认假设实现，并记进 README。
5. **交付而非 demo**：过完六条验收标准才算完成。

## 反模式

| 反模式 | 问题 | 修正 |
|---|---|---|
| 没有方案就写代码 | 方向错、返工 | 先用 agent-prd 出方案并确认 |
| 僵化工作流 | 无法适应输入变化 | 给工具，让模型决定 |
| 把所有知识塞进提示词 | 上下文膨胀 | 按需加载（s07） |
| 默默偏离方案 | 文档和代码对不上，下一轮没法迭代 | 先改方案，再改代码 |
| demo 级产出 | 无法交付 | 过全部验收标准 |
